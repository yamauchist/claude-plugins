# 合成した音声の検品

## なぜ文字起こしが要るか

- **本数・拡張子のチェックは中身を見ない。** 別のことを喋っていても通る
- **無音の分布でも足りない。** 埋め草は途切れずに喋り続けるので無音が生まれない。
  長さを固定した「え。」は30秒間ずっと意味の無い日本語を喋るのに、無音はほとんど無い

中身を見るには、音声を文字起こしして本文と突き合わせるしかない。

## `scripts/asr_check.py`

入力は「音声パス<TAB>合成に渡した本文」の TSV（1行1本。`#` で始まる行は無視。相対パスは TSV の場所から）。
**比べる本文は元の表記ではなく、実際に合成へ渡した文字列**（読み替えや記号だけの文の置換を済ませた後）にする。

```bash
uv run --python 3.11 --with faster-whisper --with pykakasi \
  python "$SKILL_DIR/scripts/asr_check.py" pairs.tsv
uv run --python 3.11 --with faster-whisper --with pykakasi \
  python "$SKILL_DIR/scripts/asr_check.py" pairs.tsv --model large-v3 --device cuda --json result.json
```

`$SKILL_DIR` はこのスキルのディレクトリの絶対パス。

- 本文も転写も pykakasi でひらがなに直し、記号・絵文字・長音「ー」を落としてから
  編集距離 / 本文長（かな CER）を取る。漢字とかなの表記揺れ（「渡辺さん」/「わたなべさん」）を吸収するため
- 既定の判定: **かな CER > 0.20** または **平均 logprob < -0.8** で要確認
- 音声ファイルが見つからない行も要確認として数える
- 終了コードは常に 0（`--strict` のときだけ要確認があれば 1）。合否ではなく、聴きに行く行の道しるべ
- 既定モデルは `medium`（CPU で実用的）

目安として、正常な音声の97%が かな CER 0.20 以下に収まる（medium / CPU）。

## 限界

- 表記揺れは かな化しても一部残る
- **Whisper は崩れた音声をもっともらしい日本語へ直してしまう** ことがある
- 記号だけの文に `…` を送って壊れた音声は「あ」と転写され、**通ってしまう**
- 声質・演技の良し悪しは測れない

したがって、挙がったものは必ず聴く。挙がらなかったものも、短い文と記号だけの文は聴いておく。

## 測り直しを減らす

`asr_check.py` にキャッシュ機能は無く、渡した TSV の全行を毎回文字起こしする。
大量に回すなら、`--json` の結果を音声ごとに保存しておき、本文や音声が変わったものだけを
TSV に並べて測り直すと速い。

## 直し方の目安

| 症状 | 原因の候補 | 手当て |
|---|---|---|
| 短い文が「ええええ」「あ、はい」と伸びる | 予測長が長すぎる | `duration_scale` を 0.6 前後に |
| 全体が早口 | 長い文に `duration_scale` を当てた | 長い文から外す |
| 文の途中に不自然な間 | 参照音声に途切れがある | 参照を作り直す（[reference-voice.md](reference-voice.md)） |
| 後半が意味の無い日本語 | `seconds` を渡している | 渡さない |
| 固有名詞の読み違い | — | 合成に渡す文字列だけ かな に置換 |
| 400 `text became empty after normalization` | 記号だけの本文 | `あ` などに置換 |
| 特定の1本だけ変 | テイクの外れ | シードを変えて作り直し、良いものの `X-Irodori-Seed` を固定 |
