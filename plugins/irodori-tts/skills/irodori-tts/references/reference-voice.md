# 参照音声（ref_wav）の作り方と選び方

Irodori-TTS の話者は、**参照音声1本の声を真似させる**方式で決まる。
参照音声の質がそのまま生成する全音声の質になるので、ここに一番手間をかける。

## 1. 参照なしで候補を作る

録音が無くても、`voice:"none"`（no_ref）と `caption` で声を作れる。

```bash
for seed in 8801 8802 8803 8804 8805 8806; do
  curl -s http://127.0.0.1:8000/v1/audio/speech -H "Content-Type: application/json" \
    -d "{\"model\":\"irodori-tts\",\"voice\":\"none\",\"response_format\":\"wav\",
         \"input\":\"ここに届くのは出されなかった手紙だけなんです\",
         \"irodori\":{\"caption\":\"二十代半ばの女性。穏やかで実直な声。\",\"seed\":$seed}}" \
    --output "ref_$seed.wav"
done
```

- no_ref はシードと caption で声が大きく動く。**4〜6本**出して選ぶ
- caption は声を決める強い入力。年齢・性別・話速・話し方まで書く
- 複数の話者を使うなら、声が似すぎないよう caption を書き分ける

## 2. 参照テキストは「1文・句読点なし・途切れないもの」

**参照音声のプロソディは、間も含めてそのまま模倣される。**

参照の中に 0.4秒以上の無音があると、生成音声の途中にも間が入る（「いらっしゃいませ。」が真ん中で切れる）。
2文つなぐより、1文・句読点なしのほうが途切れが大きく減る。

| 参照テキスト | 参照の途切れ | 生成30本の途切れ |
|---|---|---|
| 2文・読点句点あり（40字 / 8.6秒） | 2箇所 | 35箇所 / 27本に混入 |
| **1文・句読点なし（22字 / 4.6秒）** | **0箇所** | **26箇所（ほぼ読点・句点の位置の自然な間）** |

1文・句読点なしの参照なら、短い文は途切れなしになる。

## 3. 候補を測って選ぶ

```bash
uv run --with numpy python "$SKILL_DIR/scripts/measure_ref.py" ref_*.wav
```

`$SKILL_DIR` はこのスキルのディレクトリの絶対パス。ffmpeg が PATH に要る。

`measure_ref.py` は 16kHz モノラルに落とし、0.2秒フレームの RMS が -45dB 未満を無音として次を出す。
「○ 候補」の判定は途切れ・先頭の無音・発話の長さだけで行う。F0 は数値を見て自分で確かめる。

| 指標 | 採用の目安 |
|---|---|
| 途中の途切れ（発話に挟まれた 0.4秒以上の無音） | **0 箇所。必須。** 1箇所でもあると生成音声へ伝染する |
| 先頭の無音 | **0 秒。** 先頭に無音がある参照は生成音声にも間を作りやすい |
| 発話の長さ | **3〜5秒。** 短すぎると声の情報が足りない。末尾の無音は害が小さい |
| F0 中央値 | 狙った性別に寄っているか。成人男性 85〜180Hz / 成人女性 165〜255Hz が目安 |

フレームは 0.2秒刻みなので、無音の長さは 0.2秒単位に丸めて出る。

ffmpeg だけで RMS を見たい場合:

```bash
ffmpeg -v error -i ref.wav \
  -af "aresample=16000,pan=mono|c0=c0,asetnsamples=3200,astats=metadata=1:reset=1,\
ametadata=print:key=lavfi.astats.Overall.RMS_level:file=-" -f null -
```

**声質そのものの良し悪しは測れない。** 数値で絞った2〜3本を人に聴かせて決める。

## 4. 採用したら記録する

- **採用したシード・caption・参照テキストを記録しておく**（形式は自由。参照音声と同じ場所の
  メモや JSON など。例: `speaker.json` に `{"seed": "...", "caption": "...", "ref_text": "..."}`）。
  no_ref で作った参照音声は、これがあれば同じものを作り直せる
- 呼び出し側で話者ごとの既定 caption を持ち、必要なときだけ上書きできるようにしておくと便利

## 5. 参照を替えたら

- サーバーは状態を持たないので、差し替えたらそのまま合成し直せばよい（順番の制約は無い）
- **短文の予測長が変わる。** 同じ「え。」でも参照により 0.52秒 / 1.04秒と倍違う。
  `duration_scale` の閾値が合っているか、短文を数本測り直す
- 参照が変わると同じシードでも別の音声になるので、検品（[quality-check.md](quality-check.md)）からやり直す
