# Irodori-TTS で日本語音声を合成する

対象は [Irodori-TTS-Server](https://github.com/Aratako/Irodori-TTS-Server)
（上流が配っている OpenAI 互換サーバー）＋ モデル
[`Aratako/Irodori-TTS-v4-Small`](https://huggingface.co/Aratako/Irodori-TTS-v4-Small)。
ライセンスと利用条件は上流のリポジトリとモデルカードで確認すること。

必要なもの: [uv](https://docs.astral.sh/uv/)（サーバーと同梱スクリプトの実行）、
ffmpeg（`measure_ref.py`）。GPU（NVIDIA / AMD）推奨、CPU でも動く。

`scripts/` と `references/` はこのスキルのディレクトリ（スキル読み込み時に示される base directory）にある。
以下のコマンドの `$SKILL_DIR` はそのディレクトリの絶対パスに置き換えて実行する。

## 守ること（ここだけ読めば大事故は避けられる）

1. **`seconds`（生成長）を渡さない。** 渡すとその長さちょうどに生成され、
   余った分が意味の無い日本語（埋め草）で埋まる。省略すれば duration predictor が
   本文から長さを決める。同条件で長さ指定だけ変えた実測で、指定なし 0/8 破綻、
   `seconds=30` は 8/8 破綻（「え。」が30秒間喋り続ける）
2. **読める文字が6文字以下の文は `duration_scale=0.6`。** 短文は長めに予測され、
   余りがやはり埋め草になる（「え。」→「ええええええ」）。長い文には当てない（早口になる）
3. **記号だけの文（「——」「……」）はそのまま送らない。** 正規化で空になり 400 が返る。
   `…` を送るのも駄目（生成が壊れるのに文字起こしでは「あ」と読めて検品をすり抜ける）。
   代わりに **`あ`** など具体的な音を送る。表示用・保存用のテキストは元のままでよく、合成に送る文字列だけを替える
4. **参照音声は「1文・句読点なし・3〜5秒・途中の無音0」。** 参照の間はそのまま生成音声へ伝染する
5. **合成後は文字起こしで検品する。** ファイルの本数や無音の分布では、
   別のことを喋り続ける破綻を検出できない
6. **シードは文字列で持つ。** レスポンスの `X-Irodori-Seed` は 64bit。
   JavaScript の `Number` を通すと丸まって再現できなくなる

## サーバー

起動・停止・環境変数は [references/server-setup.md](references/server-setup.md)。
要点だけ:

- **`--port` を明示する。** 既定は 8088。このスキルの例はすべて 8000 を前提にしている
  （8088 のまま使うなら例の URL を読み替える）
- **`IRODORI_MODEL_PRECISION=bf16`（GPU の場合）。** 既定は fp32
- `GET /health` はモデルを読まずに答える。合成できるかは応答の `runtime.loaded` で見る
- サーバーは**状態を持たない。** 参照音声はリクエストごとに渡すので、
  話者の切り替えもキャッシュ削除も要らない

## 合成リクエスト

```bash
curl -s http://127.0.0.1:8000/v1/audio/speech -H "Content-Type: application/json" \
  -d '{"model":"irodori-tts","response_format":"wav",
       "input":"ありがとう。",
       "irodori":{"ref_wav":"/path/to/speaker.wav",
                  "caption":"落ち着いた若い女性の声。丁寧で控えめな話し方。"}}' \
  --output out.wav -D headers.txt
```

返るのは **WAV のバイト列**（48kHz / 16bit / モノラル）。サーバーはファイルを書かない。

トップレベルのキー:

| キー | 内容 |
|---|---|
| `model` | `"irodori-tts"` |
| `input` | 合成する本文 |
| `response_format` | `"wav"` など |
| `voice` | `"none"` で参照なし（no_ref）。参照音声そのものを作るときに使う |

`irodori` オブジェクトの中のキー:

| キー | 内容 |
|---|---|
| `ref_wav` | 参照音声の**絶対パス**（サーバーから見たパス。Windows なら `C:/...` のスラッシュ区切りでよい）。この声を真似る |
| `caption` | 声と話し方を**日本語の文で**書く。v4 の演技指定の本来の入口 |
| `seed` | 省略でランダム。気に入ったテイクを固定するときに渡す |
| `duration_scale` | 予測長の倍率。短文だけ 1 未満にする |
| `seconds` | **渡さない** |

レスポンスヘッダ:

- `X-Irodori-Seed` — 実際に使われたシード。**全テイクぶん記録しておく**（後から固定できる）
- `X-Irodori-Messages` — 警告と予測された長さ。短文が伸びていないかの確認に使える

PowerShell から日本語を送るときは `[System.Text.Encoding]::UTF8.GetBytes($json)` で
バイト列にして `-Body` に渡す。文字列のままだと化ける。

## 演技指定

- **まず `caption`。** 声質・年齢・速さまで強く効く。
  「落ち着いた若い男性の声。丁寧で少し硬い、控えめな話し方。」と
  「二十代半ばの男性。穏やかで実直な声。ゆっくりと丁寧に話している。」で、
  話速も年齢の印象もはっきり変わる
- **参照音声と矛盾する caption は音質を落とす**（モデルカードの注意）。
  落ち着いた参照に「叫んでいる」と書かない。大きく演技を変えるなら参照ごと替える
- 絵文字（v2 からの方式）も本文先頭に付ければ効く。同じ絵文字を重ねると強まる。
  一覧は上流の README / モデルカードにある。よく使うもの:
  😊 嬉しそうに / 😢 悲しみ / 😠 怒り / 😏 からかう / 🫣 恥ずかしそうに /
  🥺 声を震わせて / 👂 囁き / 😮‍💨 溜息 / 🤭 含み笑い / ⏸️ 間
  - v4 で絵文字が意図どおり効くかは未検証（尺が変わることだけ確認済み）。caption を優先する
- **読み間違いはテキスト置換で直す**（「辛い」→「つらい」）。合成に渡す文字列だけを替え、
  元のテキストは変えない。単純置換なので「辛いカレー」→「つらいカレー」のような誤爆に注意

## 短い文・記号だけの文

| 本文 | 指定なし | `duration_scale=0.6` |
|---|---|---|
| え。 | 1.04秒 →「ええええええ」 | 0.64秒 →「え」 |
| あ、 | 1.24秒 →「おー」 | 0.72秒 →「あ」 |
| はい。 | 1.16秒 →「あ、はい。」 | 0.68秒 →「はい」 |
| 祖母です。 | 1.36秒 →「素朴です」 | 0.80秒 →「そぼです」 |

- 「読める文字」は かな・カナ・漢字・英数字 で数える（句読点・記号・絵文字は数えない）
- **予測長は参照音声で変わる**（同じ「え。」が参照により 0.52秒 / 1.04秒）。
  参照を替えたら短文を測り直す

記号だけの文の代わりに送る音（参照固定・`duration_scale=0.6`・2シードで比較した主なもの）:

| 送る文字 | 結果 |
|---|---|
| **あ / あ…** | 安定（両シードとも「あ」） |
| は | 「はっ」になる |
| …（記号のまま） | 転写は通るが**聴くと壊れている** |

既定は `あ`。息をのむ・言いよどむなど、意図に合わせて送る音を変えてもよい（変えたら聴いて確かめる）。

## 参照音声を作る・選ぶ

手持ちの録音が無くても、`voice:"none"` + `caption` で声を作り、それを `ref_wav` に据えればよい。
手順と採用基準は [references/reference-voice.md](references/reference-voice.md)。要点:

- 参照テキストは **1文・句読点なし**（例:「ここに届くのは出されなかった手紙だけなんです」）。
  参照の途中に無音があると、生成音声の途中にも間が入る
- シードを振って4〜6本出し、`measure_ref.py` で
  **途中の無音0・先頭の無音0・発話3〜5秒** を満たすものを選ぶ。F0 中央値で性別の寄りも確かめる

  ```bash
  uv run --with numpy python "$SKILL_DIR/scripts/measure_ref.py" ref_*.wav
  ```

- 採用した参照の **シード・caption・参照テキストを記録しておく**（形式は自由。作り直せるように）

## 検品

[references/quality-check.md](references/quality-check.md)。
`asr_check.py` が faster-whisper で文字起こしし、**かなに直した CER** で本文と突き合わせる。

```bash
uv run --python 3.11 --with faster-whisper --with pykakasi python "$SKILL_DIR/scripts/asr_check.py" pairs.tsv
```

- 目安は かな CER 0.20 超、または平均 logprob -0.8 未満で要確認（表記揺れは 0.20 以下に収まる）
- **判定は道しるべであって合否ではない。** Whisper は崩れた音声をもっともらしい日本語に直すことがある。
  挙がった行は聴いて判断する。声質の良し悪しは測れないので人が聴く

## 再現性

- **シードを記録すれば音声は再現できる**（同じ本文・参照・caption・`duration_scale` で波形の相関 0.9998）。
  シード未指定だと毎回ランダムで別テイクになるので、全本の `X-Irodori-Seed` を必ず残す
- 大量に生成するなら、次を記録しておけば音声ファイルそのものを保存・バージョン管理しなくても作り直せる
  （形式は自由。本文が変わった分だけ作り直す判断にも使える）
  - 全体: Irodori-TTS-Server の上流コミット（例 `841fb7c`）とモデル名（`/health` が返す。例 `Aratako/Irodori-TTS-v4-Small`）。
    サーバーやモデルが変わると同じシードでも同じ音声になるとは限らない
  - 1本ごと: 本文（実際に送った文字列）・参照音声・caption・`duration_scale`・シード・出力ファイル
- 良いテイクが出たらその `X-Irodori-Seed` を入力データ側に書き戻して固定する
