# 担当エージェントへの依頼文

`{...}` の部分を埋めて使う。1 ラウンドの担当エージェントには、まず Agent ツールで「洗い出しの依頼」を送り、修正は同じエージェントに SendMessage で「修正の依頼」を送る。

## 洗い出しの依頼

新しい担当エージェントを起動するときの依頼文。会話の文脈に頼らず、必要なことをすべて書く。

```text
あなたはこのラウンドの担当エンジニアです。まずリポジトリを読んで改善点を挙げてもらい、
そのあと、こちらで選んだ指摘を同じあなたに修正してもらいます。
今の段階では、ファイルを一切編集しないでください（読むだけ）。修正は、後で指示があってから行ってください。

# 対象
- リポジトリ: {リポジトリの絶対パス}
- 対象範囲: {リポジトリ全体 / ユーザーが指定した範囲}
- 観点: {指定なし / ユーザーが指定した観点}
  指定がなければ、正しさ（バグ、エラー処理の漏れ）、ドキュメントとコードの食い違い、
  保守性（重複、読みにくさ）、安全性、性能、使い勝手を広く見てください。
- 対象外のファイル: {台帳の「開始時の未追跡ファイル」。なければ「なし」}
  これらはユーザーの未追跡ファイルです。対象範囲の中にあっても、指摘には挙げないでください。

# 挙げないでください
次の指摘は対応済み・見送り・保留中・失敗・却下です。同じ指摘やその言い換えは挙げないでください。
{台帳の「保留キュー」「対応済み」「見送り」「失敗」「却下」の各行。なければ「なし」}

# 基準
- 直す価値のあるものだけを挙げてください。好みの差にすぎない書き方の指摘や、
  効果に比べて変更が大きすぎるものは挙げないでください。
- 実際にファイルを読んで確かめたものだけを挙げてください。推測で挙げないでください。
- 改善点が見つからなければ、無理に挙げず「なし」と答えてください。それも正しい答えです。

# 出力形式
指摘ごとに次の形で書いてください。指摘がなければ「指摘なし」とだけ書いてください（範囲外の気づきがあれば、その後に続けてください）。
番号（#1, #2, ...）は、後の修正の指示で使います。

### #{番号} {短い題名}
- 場所: {ファイルパス:行番号}（複数可）
- 問題: {何がどう問題か。根拠となるコードや記述も示す}
- 重要度: 高 / 中 / 低
- 修正案: {どう直すか}
- ユーザー判断: 不要 / 要
  - 要の場合: {なぜ判断が要るか}と、直し方の案を 2〜3 個（それぞれの利点と欠点）

重要度の目安:
- 高: データ消失、誤動作、安全性の問題など、実害があるもの
- 中: 手順や動作を誤らせるもの、利用者が困るもの、記述の食い違いで迷うもの
- 低: 実害の小さい書き方の揃えや、小さな抜け

対象範囲の外で気づいた点があれば、指摘としては挙げず、最後に「## 範囲外の気づき」として
1 件 1 行（場所と問題）で短くまとめてください。範囲外のファイルは、後の修正でも直しません。
次の範囲外の気づきは記録済みなので、挙げないでください: {台帳の「範囲外の気づき」の各行。なければ「なし」}
```

## 修正の依頼

同じ担当エージェントに SendMessage で送る文。自動修正のときも、相談後の修正のときも、この形を使う。

```text
次の指摘を修正してください。ここに挙げていない指摘は、今は直さないでください。

# 触ってよい範囲
{対象範囲。この外のファイルは変更しないでください}
次のファイルは、対象範囲の中にあっても変更しないでください: {台帳の「開始時の未追跡ファイル」。なければ「なし」}
.gitignore で無視されているファイルを、手で編集・作成しないでください（テストやビルドが自動で作るキャッシュや成果物は構いません）。

# 直す指摘
{コミット単位ごとに見出しを分けて書く（例:「## 単位 1: #2, #5」）。各単位の中に次を書く}
{あなたが挙げた指摘の場合: 番号と題名、修正方針。あなたの修正案どおりなら「修正案どおり」と書く。
 違う直し方にする場合は、その方針をはっきり書く}
{前のラウンドで挙がった指摘・相談した指摘の場合: 台帳の ID、題名、場所、問題、
 ユーザーが選んだ案と補足をすべて書く（あなたはこの指摘をまだ知らないため）}

# 今は直さない指摘
{このラウンドで挙がったが、要判断・却下にした指摘の番号。なければ「なし」}

# 守ること
- 指摘を直すのに必要な変更だけをしてください。ついでのリファクタリングや整形はしないでください。
- 周りのコードの書き方（命名、コメントの量、言い回し）に合わせてください。
- コミット、ブランチの切り替え、push はしないでください。コミットはこちらで、単位ごとに行います。
- `git add` / `git mv` / `git rm` など、インデックスを変える操作もしないでください。ファイルの移動や削除は、通常のファイル操作で行ってください。
- 単位をまたいで同じ変更を混ぜないでください（ある単位の修正のついでに、別の単位の箇所を直さない）。
- テストやリンターがあれば、変更に関係するものを走らせてください。
- 指摘が誤りだった、または直すと別の問題が出るとわかった場合は、無理に直さず、その理由を報告してください。

# 報告
単位ごとに次を書いてください。
- 単位: {番号}
- 指摘ごとの結果: 番号または ID: 修正した / 修正しなかった（理由）
- 変更したファイル（この単位で触ったものだけ。新しく作ったファイルと削除したファイルも含める）
- 走らせたテスト・リンターとその結果（走らせていなければ「なし」）
```
