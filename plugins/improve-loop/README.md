# improve-loop

リポジトリの改善を、サブエージェントによる「洗い出し → 修正」のループで繰り返すプラグインです。`improve-loop` スキルが 1 つ入っています。

## 流れ

1. 新しいサブエージェントに、リポジトリ（または指定した範囲）の改善点を挙げさせる
2. ユーザーの判断が要らない指摘は、洗い出したのと同じサブエージェントにすぐ直させる
3. ユーザーの判断が要る指摘は、4 件まで保留する
4. 4 件たまったら（または中以上の指摘がなくなったら残りを）、まとめて方針を相談し、選んだ方針でそのラウンドのサブエージェントに修正させる
5. 1 に戻り、また新しいサブエージェントに洗い出させる

重要度が「中」以上の指摘がなくなるか、ユーザーが「止めて」と言うまで続きます。中以上がなくなった時点で保留中の指摘があれば相談し、その相談で修正を入れたときだけ、確認のためにもう 1 ラウンド回します。確認のラウンドでも中以上が出なければ、残った指摘を最後に 1 回だけ相談して終えます（この最後の修正は、別のサブエージェントの確認を経ません）。修正が別の問題を生み続ける（直した箇所への指摘が 3 ラウンド続く）ときは、いったん止めて方針を聞きます。

洗い出しと修正を同じサブエージェントに任せるので、洗い出しで読んだコードの文脈をそのまま修正に使えます。ラウンドが変わるたびにサブエージェントを新しくするのは、前のラウンドの見方に引きずられず、新しい目で見させるためです。

## インストール

```
/plugin marketplace add yamauchist/claude-plugins
/plugin install improve-loop@yamauchist-plugins
```

## 使い方

Claude Code に次のように頼むと、スキルが起動します。

- 「このリポジトリの改善ループを回して」
- 「`src/api` を見て、指摘がなくなるまで改善して」
- 「ドキュメントを中心に改善を回して」

範囲や観点を言わなければ、リポジトリ全体を広く見ます。範囲を指定すると、洗い出しも修正もその範囲に限ります。

## 動き方の補足

- 判断が要るかどうかは、メインの Claude が指摘を 1 件ずつ確かめて決めます。振る舞いや仕様が変わるもの、直し方が複数あるもの、削除、依存の追加などは、迷ったら相談に回します。
- 相談は選択式の質問で、1 回に最大 4 件です。どの指摘も「見送る」を選べます。見送った指摘は以後挙がりません。
- 経過は、リポジトリの外に置く台帳ファイルに記録します。リポジトリの中にはファイルを作りません。
- 修正は、差分を確かめたものから、原則として指摘 1 件ごとにコミットします。既定ブランチにいる場合は、作業用ブランチを切ってよいかを最初に聞きます。断ると、どのブランチで作業するか（既存のブランチか、中止か）を聞き直します。既定ブランチに直接コミットするのは、そのときに既定ブランチを明示した場合だけです。push はしません。
- git リポジトリが必要です。git リポジトリでなければ始めず、`git init` してよいかを聞きます。コミットが 1 つもない場合も始めません（最初のコミットを作ってから使ってください）。
- 未コミットの変更がある状態では始めません。先にコミットするか退避してください。未追跡ファイルはそのままでかまいません（開始時の一覧を控え、ループで作られたファイルと区別します）。ただし、開始時の未追跡ファイルは洗い出しも修正もしません。見てほしいファイルは先にコミットしてください。
- 毎ラウンド、リポジトリを読み直すサブエージェントを起動するため、トークンの消費は多めです。
